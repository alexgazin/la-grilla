# La Grilla · роадмап 100 идей (сборки 47–60)

Документ продолжает [продюсерский план 44–46](PRODUCER_ROADMAP_PROMPT_RU.md). Он раскладывает 100 идей развития по волнам, файлам кода, критериям приёмки и внешним зависимостям. Базовый исходник — `d298c17` (`main`, сборка 43, схема проекта 15). Работа идёт в ветке `claude/determined-goldberg-jzngwg`. Каждая волна — отдельная серия коммитов с префиксом номера идеи (`I07: …`).

## Принципы, общие для всех волн

1. **Одна музыка везде.** Всё, что слышно вживую, должно совпасть с записанным, WAV, стемами и MIDI. Новые звуковые механизмы проходят через общий компилятор `Compiler` и ядро `GrillaKernel`, без отдельного пути «только для экрана». Каждая звуковая функция получает host-тест сравнения live/offline (образец — `Tests/keyboard_level_test.cpp`).
2. **Формат проекта.** Новые поля — `Optional` со значением по умолчанию `nil`. Схема повышается на единицу и получает шаг миграции в `ProjectDocument.migrated`. Тест обязателен: старый файл читается, новый сохраняется, старое приложение отклоняет новый файл без потери исходника.
3. **Защита пользовательского.** Сыгранные руками ноты, назначения SoundFont, личные наборы и редактируемые исходники пэдов не меняются без явного действия. Генераторы и пакетные правки работают через предпросмотр, применяются одной транзакцией `History.apply` и отменяются одним Undo.
4. **Реальное время.** В аудиоколбэке нет аллокаций, блокировок, файлов и сети. Новые DSP-блоки проверяются тестом нулевых аллокаций (образец — `Tests/render_stress_test.cpp`).
5. **RU/EN, ночная тема, iOS 18+, доступность.** Каждая строка UI добавляется в `Resources/{en,ru}.lproj/Localizable.strings` и проходит `scripts/audit_presentation.py`. Каждый элемент управления получает accessibility-label и цель касания не меньше 44 pt.
6. **Доказательства.** Логика — Swift Testing в `Packages/MusicDomain/Tests`. Звук — C++ host-тесты в `Tests/`. Пользовательский путь — XCUITest в `UITests/`. Снимки экрана снимаются только с работающего приложения. Физические замеры — в [DEVICE_ACCEPTANCE](release/DEVICE_ACCEPTANCE.md). Если устройство или доступ недоступны, пункт помечается «заблокирован», а не «готов».

## Статусы

`план` → `в работе` → `программно готов` (логика и тесты на хосте) → `проверен на симуляторе` (XCUITest в CI) → `проверен на iPhone` → `готов к приёмке`. Отдельная пометка **«нужен владелец»** ставится там, где нужны Apple Developer, App Store Connect, entitlements, физическое железо или юридическое решение.
