# LaGrilla Design26: interaction and skill reference research

Read on 2026-11-17 via the connected GitHub read tools. This is a reference synthesis for a native SwiftUI music studio. No external repository instructions were executed, no skills were installed, and no application, project, deployment, or dependency files were changed. Only this research artifact and the Stageshow companion report were written.

Evidence labels: **Source** means a statement or example actually present in the pinned repository. **Recommendation** means our application to LaGrilla; it is not claimed to be a requirement or implementation already present in a source. The web examples were inspected as text; no browser, iOS build, audio-latency measurement, or physical-device haptic verification was performed in this research task.

## Findings grounded in source

### Hallmark

- **Source:** README positions Hallmark as a website/page skill. `SKILL.md` is an HTML/CSS workflow with website gates, theme dealing and browser linting. These are external reference instructions, not an instruction hierarchy for LaGrilla.
- **Source:** [`microinteractions.md` L7–16](https://github.com/Nutlope/hallmark/blob/04977e15f3dfd6ee4b74c887dac3eb52665d6c92/skills/hallmark/references/microinteractions.md#L7) says motion must clarify, guide or confirm; visible success needs no toast; reduced spatial motion becomes a 150ms opacity crossfade while functional state changes still happen. Its tokens are 120ms micro, 220ms short and 420ms long; exits use 60–75% of enter time. The spring allowance is limited to a declared playful posture.
- **Source:** The same file L52 supplies drag feedback: a ghost, accent drop target and 220ms release snap with no spring; arrow keys reorder and a live announcement communicates the move. L73–78 calls a `brisk` character 0.85–0.9 times the base timing, appropriate to an instrument panel.
- **Source:** [`interaction-and-states.md` L7–16](https://github.com/Nutlope/hallmark/blob/04977e15f3dfd6ee4b74c887dac3eb52665d6c92/skills/hallmark/references/interaction-and-states.md#L7) explicitly lists default, hover, focus, active, disabled, loading, error and success. Loading keeps the label readable and width stable; errors need a message and semantic state, not color alone; success must reflect a real result. L81–89 favors Undo for reversible actions, helpful empty states and a reason near disabled controls.
- **Source:** [`craft.md` §5–6](https://github.com/Nutlope/hallmark/blob/04977e15f3dfd6ee4b74c887dac3eb52665d6c92/skills/hallmark/references/craft.md) reserves linear motion for progress/scrubbing, forbids overshoot on UI state, and recommends loading feedback after 150–300ms with no flicker. These are website recipes, not audio trigger timing.
- **Source:** [`dark-mode.md`](https://github.com/Nutlope/hallmark/blob/04977e15f3dfd6ee4b74c887dac3eb52665d6c92/skills/hallmark/references/dark-mode.md) derives dark tokens instead of inverting; elevated dark surfaces become lighter, separators remain visible and contrast is independently checked. [`themes/midnight.md`](https://github.com/Nutlope/hallmark/blob/04977e15f3dfd6ee4b74c887dac3eb52665d6c92/skills/hallmark/references/themes/midnight.md) demonstrates a calm night instrument with layered blue surfaces and an azure signal; it is deliberately square, still and free of bloom/glass.
- **Recommendation:** Keep the liked night theme and make its controls more legible through surface/value steps, a consistent selected outline/fill, and stable labels. Do not copy Midnight’s exact typeface, square corners, photo treatment or cold-blue palette merely because the app is musical. Hallmark’s `05-workbench.md` is a marketing page about app captures, not the layout of the actual music workbench.

### Make Interfaces Feel Better

- **Source:** [`SKILL.md`](https://github.com/jakubkrehel/make-interfaces-feel-better/blob/1a2aa9695487dc6d2a59af28e34db9b1490ab181/skills/make-interfaces-feel-better/SKILL.md) says to use the existing styling system, inspect hover/focus/active/loading/empty, and never add a second styling system merely for polish. In this app the corresponding system is native SwiftUI, not Tailwind or a React motion package.
- **Source:** [`animations.md` L5–41](https://github.com/jakubkrehel/make-interfaces-feel-better/blob/1a2aa9695487dc6d2a59af28e34db9b1490ab181/skills/make-interfaces-feel-better/animations.md#L5) explains that interactive motion must retarget to latest intent. L387–390 explicitly says **no custom animation on high-frequency interactions**: repeated interactions get instant feedback or ≤150ms opacity/background-color; every animated change needs a static cue; honor reduced motion.
- **Source:** The same file has a general press recipe of scale 0.96 over 150ms, with a `static` prop for contexts where movement distracts. Contextual icon recipes use opacity/scale/blur, a 0.3s spring and `bounce: 0`; exit examples are typically 150ms versus a 300ms entrance. These are concrete web recipes, not universal native values.
- **Source:** [`surfaces.md`](https://github.com/jakubkrehel/make-interfaces-feel-better/blob/1a2aa9695487dc6d2a59af28e34db9b1490ab181/skills/make-interfaces-feel-better/surfaces.md) distinguishes structural/state borders from decorative elevation, suggests optically shifting a play triangle, computes close nested corners as outer radius = inner radius + padding, and warns enlarged hit areas must not overlap adjacent controls.
- **Source:** [`typography.md`](https://github.com/jakubkrehel/make-interfaces-feel-better/blob/1a2aa9695487dc6d2a59af28e34db9b1490ab181/skills/make-interfaces-feel-better/typography.md) recommends tabular digits for changing timers/counters and retaining the existing type family. [`icons.md`](https://github.com/jakubkrehel/make-interfaces-feel-better/blob/1a2aa9695487dc6d2a59af28e34db9b1490ab181/skills/make-interfaces-feel-better/icons.md) gives selected/active fill a meaning, accessible names for icon buttons and says media playback symbols do not mirror for RTL.
- **Recommendation:** Use static onset highlight for every pad and piano key. Reserve any scale press for infrequent toolbar controls, keeping hit geometry fixed. Use `.monospacedDigit()` for BPM, bar/beat position, duration and numeric mixer values. Use SF Symbols and native semantic colors/traits rather than copying SVG stroke values or macOS CSS font smoothing.

### UI UX Pro Max

- **Source:** README and `.claude/skills/ui-ux-pro-max/SKILL.md` explicitly support SwiftUI and app/native rules. The skill prioritizes accessibility and touch before motion and says to detect the real stack. Its `--motion` output attaches GSAP snippets; the separate `motion.csv` is a web animation preset catalog.
- **Source:** [`references/pro-rules.md` L5 and L16–34](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/e59ff376a41f7ca47b7541ad5c116495cbade3ee/.claude/skills/ui-ux-pro-max/references/pro-rules.md#L5) explicitly scopes the file to native/mobile. It requires stable press bounds, 44pt iOS touch areas, accessible state/name, normal text contrast ≥4.5:1, meaningful icon/control contrast ≥3:1, native interactive primitives, safe areas, and one primary gesture per region. Its tap feedback example is 80–150ms, while quick-reference lists within 100ms; these are broad responsiveness targets, not reasons to delay feedback.
- **Source:** [`quick-reference.md` L48–53](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/e59ff376a41f7ca47b7541ad5c116495cbade3ee/.claude/skills/ui-ux-pro-max/references/quick-reference.md#L48) says use haptics for confirmations/important actions, avoid overuse, supply visible alternatives to core gestures, and apply a drag threshold. L136–160 calls for context-aware shared timing tokens, interruptibility, no blocked input, finger-tracking drag/pinch, explicit final semantic state and no correctness dependency on animation completion.
- **Source:** [`app-interface.csv`](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/e59ff376a41f7ca47b7541ad5c116495cbade3ee/src/ui-ux-pro-max/data/app-interface.csv) rows 6–15 distinguish 44pt iOS, 48dp Android and 24 CSS px web; preserve screen state; cap bottom tabs at five; give sheets a close affordance; show local error explanations. Rows 23–25 recommend 150–300ms native micro-interactions, reduced-motion handling and no decorative infinite loops. Rows 30–31 prohibit gesture-only critical actions and require a non-drag alternative.
- **Source:** [`swiftui.csv`](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/e59ff376a41f7ca47b7541ad5c116495cbade3ee/src/ui-ux-pro-max/data/stacks/swiftui.csv) includes NavigationStack/NavigationSplitView, stable identifiers, `.task`, `ProgressView`, `@Environment(\.accessibilityReduceMotion)`, Dynamic Type, semantic Button and SwiftUI performance profiling. It is guidance data, not app source or a validated implementation.
- **Source caution:** `ux-guidelines.csv` gives a haptic example using `navigator.vibrate(10)` even though its row is mobile; this is a web API and not the SwiftUI implementation. Some compact datasets contain generic or oversimplified advice. Choose the native outcome and verify native API availability instead of copying examples wholesale.

## Proposed native interaction contract for LaGrilla

The following are **recommendations**, synthesized from the evidence above. None is a claim that one repository already implements LaGrilla or mandates these exact SwiftUI choices.

| Surface | Behavior and feedback | Motion and haptics | Visible/accessible alternative |
| --- | --- | --- | --- |
| Performance pads and piano keys | Start the existing sound trigger at touch onset, set a held/playing highlight immediately, and release/cancel cleanly. Distinguish held, selected sound and muted states using shape/outline/label as well as color. Keep controls stationary and support repeat input during other transitions. | Do not await an animation, debounce, haptic or panel transition before audio. No per-hit entrance, spring bounce, blur or ripple queue. A short color/opacity release ≤120–150ms is enough. Avoid haptics on every repeated note by default. | Label note/sound and relevant selected/muted state; maintain the native accessible action path alongside any custom touch implementation. Enlarged touch regions must not overlap. |
| Piano size divider | Always show a grabber plus a `Keyboard height` affordance; while resizing, geometry tracks the finger directly and the label/key content lays out at its real size. Persist chosen height. | No smoothing lag while held. On release, settle only to the chosen bound/detent, with an interruptible ~220ms no-bounce transition if useful. One selection haptic when entering a new meaningful detent, not each pixel. | Provide Compact / Standard / Large or minus/plus controls with VoiceOver adjustable action; show an explicit accessible value. |
| Sound browser preview | Keep selection and audition distinct: row selects the sound, a named Preview/Stop control auditions it. A stable trailing slot shows loading/playing/error; keep row width and text fixed. A new preview replaces/cancels the previous one. | Sound starts as soon as ready; do not delay for an icon animation. Native play/pause symbol replacement may crossfade ~120–220ms. No decorative continuous waveform when no sound plays. | Name audition target and expose playing state. `Loading sound…`, `Could not preview. Try again.` and explicit Retry/Stop are visible. Preserve browser position/filter when returning. |
| Transport | Keep Play/Stop/Record in a persistent safe-area-aware group; recording state includes a symbol and `Recording` text/value. Stable tabular BPM/bar/beat. Destructive/clear actions sit apart. | Native discrete press highlight, optional single light confirmation haptic on transport/record state change. Playhead/progress follows the actual engine clock, not ease-in/out; do not interpolate audio state through UI animations. | Icon labels change with action (`Play`, `Stop`, `Start recording`); announce coarse state changes, not every beat. Keep a visible stop action when recording/previewing. |
| Sequencer/grid | Keep tap, drag/move, resize and scroll/pinch modes unambiguous. Tap selects/toggles as the existing product intends; dragging has a threshold and distinct handle/mode, preserves an origin ghost and shows destination/snap. Preserve project/grid position across sheets. | While held, follow finger without a spring. Commit snapped state immediately; optional ≤220ms visual settle. One haptic on selection/commit or changed coarse detent, not every crossed cell. | Visible mode labels, Undo and accessible move/length/velocity controls; do not make hidden long press, two-finger drag or edge precision the sole core path. Respect system back/edge gestures. |
| Navigation and panels | Core composition remains the destination. Use a small labeled mode selector or at most five true top-level tabs; keep library/settings secondary. Present inspectors with native sheets/popovers and a clear close action; returning preserves active sound, scroll, selection and working state. | Use native transition defaults for navigation. A ~220–300ms non-bouncy spring is a candidate for an infrequent inspector expansion; reduce/remove it if it delays rapid use. Avoid a separate entrance for every row/tab/pad. | Active mode has icon/label/selection semantics, not color alone. Support Dynamic Type by reflowing chrome and disclosing secondary controls rather than making performance surfaces tiny. |
| Optional tilt | Treat as an opt-in decorative treatment on a non-critical visual layer only. Touch geometry and control labels remain fixed. | Clamp strongly, stop when not visible/active, disable under Reduce Motion. Do not add tilt to the playable grid, keys, pads or transport. | A visible preference can turn it off; all function is available without device movement. Source basis is general restraint/reduced-motion, not an endorsed native tilt recipe. |

### A small motion vocabulary

| Token/condition | Starting recommendation | Evidence and limit |
| --- | --- | --- |
| Immediate input | Audio scheduling and semantic held/playing state on touch onset; no artificial wait | Inference from Stageshow input onset, Jakub repeated-input restraint, UI Pro Max no-blocking and finger tracking. Generic ≤100ms tap guidance is not an audio-latency specification. Measure on a device. |
| Micro state | 120ms opacity/color release; pressed state can be immediate | Hallmark micro token + Jakub ≤150ms ceiling for repeated interactions. No forced interpolation of note events. |
| Menu/selection/inspector detail | About 220ms; native defaults where already suitable | Hallmark short token; UI Pro Max warns no universal duration. Retarget new state mid-flight. |
| Infrequent panel geometry | ~220–300ms no-overshoot spring candidate; ≤420ms only for a genuinely larger/modal transition | Jakub 300ms zero-bounce contextual spring; Hallmark 420ms modal; native spring parameters are a proposal and require app testing. |
| Exit | Shorter than matching enter, roughly 60–75%, except native transitions kept intact | Hallmark + UI Pro Max. Jakub prefers ease-out for both; do not blend easing systems per component. Favor native system motion. |
| Direct manipulation | No tween between held finger and manipulated geometry; linear engine-clock progress | Stageshow motion and UI Pro Max gesture feedback; Hallmark allows linear scrubbing/progress. Settle only after release. |
| Reduce Motion | Keep the final state and all function; remove spatial motion, tilt, bounce and decorative loops. Use an optional brief opacity crossfade up to 150ms. | Hallmark gives 150ms crossfade; Jakub explicitly allows immediate removal; SwiftUI dataset exposes `accessibilityReduceMotion`. |

No source provides a device-validated universal SwiftUI spring response/damping pair or LaGrilla audio latency threshold. Use `.spring(duration:bounce:)` only when supported by the app’s deployment target, or the established native animation API; do not add a dependency for this research.

### State feedback and copy

| State | LaGrilla recommendation |
| --- | --- |
| Ready | Show the actual selected sound, playable grid and current transport state; no synthetic loading or page reveal on re-entry. |
| Pressed/held | Immediate static surface/outline change; hit bounds stay fixed. Release/cancellation clears held state reliably. |
| Loading | Reserve the content’s shape; small local `ProgressView` or stable sound-row slot for expected waits. Avoid flashing for near-instant work and show explicit text/recovery for long waits. Keep unrelated playable controls available. |
| Empty project | `No notes yet.` / `Tap a pad or add notes to start a pattern.` One useful action such as `Add sound` or `Record`, chosen from actual available behavior. Do not invent functionality or show a false waveform. |
| Empty sound results | `No sounds match “…”` with `Clear filters`; preserve query and make recovery visible. |
| Error | Explain the failed operation nearby: `Could not load this sound. Try again.` Keep the existing usable state, expose Retry, and announce the meaningful status through native accessibility. Never report success before a real result. |
| Success | Let the resulting selected sound, saved title or new notes show the result. Use a brief labeled confirmation only when the effect is otherwise invisible. Hallmark discourages success toasts; UI Pro Max allows them. Choose low-noise visible feedback for a performance app. |
| Disabled | Native disabled semantics, reduced visual emphasis and a nearby reason where unclear, e.g. `Select a sound to preview.` Do not rely on a dim color alone. |
| Destructive edit | Provide visible Undo for reversible note/pattern edits. Confirm only actions with material loss that cannot be undone; choose native wording and scope. Hallmark’s typed-name confirmation for account/table deletion is not a recipe for ordinary music edits. |

### Night theme and density

Keep the existing night palette the user likes. Define semantic roles for canvas, inset track, raised inspector, pressed surface, selected surface, primary/secondary text, separator, playing, recording and error. Use a brighter value step for raised surfaces, a quiet real divider for structural seams, and a clear selected edge. Do not add glow to every pad or glass to every panel. Ensure secondary normal-size text also meets 4.5:1; meaningful icons/state boundaries need 3:1. Those numeric ratios are source targets; no LaGrilla color pair was measured in this task.

Preserve the workspace’s useful density through grouping and progressive disclosure: transport stays visible; clip/grid/piano are the main canvas; detailed sound parameters live in an inspector. Size native touch areas in points, not CSS pixels. A thin visible divider can have a generous non-overlapping touch region and still needs a labeled non-drag alternative. Avoid duplicating mode selectors in both a bottom tab bar and a same-level sidebar. Landscape, larger text and small-phone variants need real layout review.

## What transfers, and what does not

- **Transfer principles:** immediate causality, interruptibility, real state as feedback, fixed geometry, readable state contrast, visible gesture affordances, predictable navigation, stable numeric slots, purposeful haptics, and reduced-motion parity.
- **Do not directly port:** CSS transforms/`transition`/pseudo hitboxes/ARIA/HTML dialogs, DOM focus management, Tailwind, GSAP, Framer Motion, browser animation panels, `navigator.vibrate`, web font smoothing, web viewport breakpoints or 44 CSS px targets. Express equivalent outcomes in native SwiftUI and iOS semantics. A web ban on animating CSS width/height does not prohibit direct native resizing; the useful requirement is real geometry, finger tracking and no stretched text.
- **Do not let marketing choreography set product timing:** Hallmark hero reveals, Stageshow staged demos and Pro Max scroll/GSAP presets are reference materials, not a mandate to animate a working music studio. Pads and transport should be available immediately.
- **Resolve source conflicts with context:** Hallmark generally favors restrained non-spring UI; UI Pro Max favors springs for natural native feel; Jakub allows a specific zero-bounce contextual spring and prohibits high-frequency custom motion. For LaGrilla, keep repeated input static and immediate, use native no-overshoot panel motion sparingly. Likewise choose native semantic button/accessible action behavior rather than blindly copying web-specific exact values.
