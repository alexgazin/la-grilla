## Translation to native LaGrilla (recommendations / inference)

1. **Pad and piano onset:** trigger the audio and pressed visual on touch-down. Keep any release animation out of the audio path. A shallow scale/fill change can echo the 0.97 press, but use native touch ownership, cancellation and multi-touch semantics. A source advertising demo’s awaited `click()` must never add musical latency.
2. **Piano resize:** show a persistent resize affordance and current usable keyboard immediately. During drag, geometry follows the finger without spring smoothing; key labels and touch coordinates remain stable. On release, settle to a useful size using an interruptible SwiftUI animation, retaining current geometry on a second grab. Geometry changes must not stretch key text. These are inferred applications of L94/L142, not supplied native implementation.
3. **Sound preview:** keep preview’s action slot anchored while it changes idle → loading → playing → stopped/error; separate selection from preview when both exist. Show audio activity on the previewed row itself. Errors belong beside that row with a retry action. Keep modal headers and main workspace transport stable while data changes.
4. **Transport:** retain one button/control identity through play, pause, record and pending states. Give recording both explicit text/symbol and semantic color. Playhead motion can be continuous; labels and controls should not bob or pulse after a state settles. Haptic confirmation should indicate intentional mode changes or snap boundaries, not every sequencer tick or note. **Haptic design here is inference:** no haptic API or prescription was found in the read source.
5. **Grid gestures:** retain finger-to-note grab offset; drag state follows touch exactly; snap destination is a distinct stable cell. Do not spring held notes behind the finger. Avoid stacking optional tilt onto precision note editing. Reserve lift or slight tilt, if used at all, for explicitly carried objects outside time-critical pad input.
6. **Night theme:** preserve the already-liked LaGrilla night identity. Use a limited neutral surface ladder and one focus accent; brighter surfaces convey floating/active panes. Apply status colors semantically, retaining visible symbol/text distinctions. The source’s music neutrals can inform a ladder; copying its desktop/sidebar/cropped bento layout would undermine the native app.
7. **Reduced Motion:** use SwiftUI `accessibilityReduceMotion` to suppress decorative tilt, overshoot, large scale and travel; retain direct position updates, legible pressed/focus states and functional playhead timing. Render the settled target geometry. Do not freeze a live music app into the marketing kit’s static poster.
8. **State completeness:** preserve useful workspace chrome during loading; use placeholders only for genuinely pending data at final geometry; keep empty-state guidance within the real grid/library and offer a concrete next action. Preserve retryable error context. Empty-state copy/action choices are inference; no dedicated empty-state implementation was found among read examples.

## Bounds of the evidence

- Stageshow supplies useful continuity, causality, geometry and visual hierarchy judgment, plus inspectable CSS and React examples. It supplies no SwiftUI production code, no verified musical/audio latency guidance, no haptic scheme and no universal spring specification.
- Staggered row/grid reveals, 0.8–1s arrivals, 10–16s loops, synthetic cursors, filler bars, cropping rules and small default heights belong to product illustration. Native navigation should use platform semantics and actual task density; neither its desktop page-crossfade recipe nor its toy phone flow establishes native app navigation rules.
- Repository setup/filming commands were read as reference and were not run. No repository code, dependencies, assets, or fonts were installed or adopted.
